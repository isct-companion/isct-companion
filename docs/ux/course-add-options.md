# 批量加课：5 个交互方案（用于生成可交互原型）

> 给原型生成者：本文档自包含，不需要其他上下文。请为 **方案 A–E 各生成一个独立的可交互 HTML 原型**（单文件，可直接在浏览器打开），全部使用第 4 节的同一份示例数据，并让第 3 节的 5 个场景都能在原型里实际点一遍。原型页面里**不要写方案说明文字**，只呈现界面本身，方便使用者并排比较手感。

## 1. 背景

一个桌面 app（macOS），帮东京科学大学（Science Tokyo）的学生管理课表。本文只关心 **Courses 页里"批量把课加进某个学期"** 这一件事，目标是**最省心**：步骤最少、少打字、少确认、不弹窗、不切页面。

学校的官方选课在学校系统里完成；这个 app 里的"加课"只是把课放进自己的课表或计划里，不会提交给学校。

## 2. 所有方案共同的界面约束

- 窗口 1280×820，**页面本身不滚动**（面板内部可以滚动）。
- 左侧一条窄导航：Today / Schedule / Courses / Web，底部是 Settings。
- Courses 页顶部：学期标签（2026 2Q · **2026 3Q**（当前）· 2026 4Q · ＋），右侧是全局操作区。
- Courses 页主体有一张周课表：周一到周五 × 第 1–10 节，最下面另有一行"集中/其他"，放集中讲义、只申告不排课的科目。节次对应的时间：1-2 节 08:50–10:30，3-4 节 10:45–12:25，5-6 节 13:30–15:10，7-8 节 15:25–17:05，9-10 节 17:15–18:55。
- 一门课一般一周上两次（例如"火3-4 / 金3-4"），加课时两个格子要同时占上。
- 课程状态有四种，用不同的强度显示：
  - **Registered**：学校已正式登録，实色；
  - **Declared**：在学校系统里已申告、还没正式登録，实色加小标记；
  - **LMS**：只是出现在学习平台里，虚线框；
  - **Planned**：自己计划的，低对比度。
- 冲突：同一个时间格里有两门课时标红，但**不阻止**添加。
- 课名有日文和英文两种，界面右上角可以切换显示语言；课程代码（如 `CSC.T341`）两种语言都一样。
- 推荐标记来自本学系的推荐课程表，由"群字母 + 标记"组成：`A ○`、`B ○`、`C ○`、`R ◎`（◎ = 必修，○ = 推荐）。
- **已修得（有成绩）的课不应该再被建议**，也不能被重复加入；搜索结果里可以显示它们，但要标成"已修得"并置灰。
- 每次批量添加之后，屏幕底部出现"已加入 N 门 · 撤销"的提示条，持续 6 秒。
- 视觉风格：温暖的中性色背景，克制的蓝色作为强调色，排版清晰，标签短，不写教程式的说明文字。

## 3. 每个原型都要能走通的 5 个场景

- **S1 从学校同步**：点击同步（Pull）。LMS 和学校选课系统返回数据后，课表里自动多出 1 门之前没有的课（`CSC.T272`，状态为 LMS）。同时要告诉用户"新增 1 · 无变动"。
- **S2 批量加推荐课**：从本学系的 3Q 推荐课里一次加入 4–5 门，**在加入之前**就能看到总学分和冲突。
- **S3 粘贴代码**：朋友发来一段文字（见 4.5），粘贴后识别出里面的课程代码并加入。无法识别的代码（`CSC.T999`）和已修得的课（`CSC.T241`）要明确标出来。
- **S4 填空档**：周二 3-4 节是空的，从这个时间段可选的课里挑一门加进去。
- **S5 撤销**：撤销 S2 刚才的批量添加。

## 5. 五个方案

五个方案的思路互相不同，请忠实按各自的描述实现，不要把它们做得彼此相像。

### 方案 A — 建议清单（右侧常驻面板）

**核心想法**：app 已经知道你大概要上什么课，所以默认动作是"勾选并确认"，而不是去搜索。

- 布局：左边约 60% 是课表，右边约 40% 是常驻的"3Q 建议"面板。
- 面板按分组列出，每组都可以折叠：
  1. 必修 ◎，默认勾上；
  2. 推荐 ○（本学系），默认不勾；
  3. LMS 里有、课表上还没有的课（S1 同步后出现）。
- 每一行包括：勾选框、代码、课名、时间、学分、推荐标记，冲突时加一个标记。
- **鼠标悬停或勾选某一行时，课表上用半透明块预览它会占哪些格子**，冲突格标红。
- 面板顶部固定显示汇总和按钮，例如："已选 5 · 11 学分 · 1 冲突 [加入 5 门]"。
- 面板顶部还有两个图标按钮：同步（S1），和"粘贴"（S3）。粘贴后识别出的课作为一个新分组出现在面板最上面。
- S4：点课表上的空格子，面板临时切换成"该时间段候选"列表（推荐的排在最前），可以勾选加入，然后回到建议列表。

### 方案 B — 课表直接点（格子弹出候选）

**核心想法**：一切操作都在课表上完成，没有侧边面板。

- 布局：课表占满整个主体区域。
- 点任意一个格子，在格子旁边弹出一个锚定在格子上的小浮层（不是模态对话框），列出这个时间段的候选课，推荐的排在最前。点一门课就立刻加入，浮层不关闭，可以继续加。
- **按住 Shift 拖选多个格子**（例如整个周二），浮层里列出能覆盖这些格子的所有候选。
- 一门课一周两次时，鼠标悬停在候选项上，另一个格子也会同时高亮。
- 课表顶部有一条细的"推荐覆盖条"：一排小色块，每个色块代表一门本学期的推荐课，点击就加入（S2 可以连点几下完成）。
- 同步（S1）和粘贴（S3）是右上角的两个按钮；粘贴后课表上直接出现待确认的虚影块，点"全部加入"才真正加入。

### 方案 C — 暂存篮（先摆出来看效果，再一次性应用）

**核心想法**：所有入口都先把课放进"暂存篮"，课表实时显示"如果全部加入会是什么样"，最后一次性应用。

- 布局：课表在上方，底部是一条可以展开的暂存篮（收起时约 64px 高）。
- 往暂存篮里放课的入口都在顶部：搜索框（结果带"＋"）、"推荐"按钮（展开推荐列表）、同步、粘贴、点课表格子。
- 暂存篮里的课在课表上显示为带斜纹的虚影块，和已有的课一起看；冲突格标红。
- 暂存篮展开后显示每门课，可以单独移除；顶部写着"5 门 · 11 学分 · 1 冲突 [应用] [清空]"。
- 应用之前，已有的课表完全不受影响；可以随时清空重来。
- S5：撤销"应用"这一步，暂存篮里的内容恢复原样。

### 方案 D — 命令栏（一个输入框完成所有事）

**核心想法**：像 Spotlight 那样的一个输入框，用键盘就能完成所有加课。

- 布局：课表占满主体区域，顶部居中有一个宽输入框（快捷键 ⌘K 聚焦）。
- 输入框能理解多种输入，下拉结果实时出现，每一行都能勾选：
  - 课程代码或课名："CSC.T341"、"データベース"、"database"；
  - 时间："火3-4"、"tue 3"；
  - 关键词："推荐"、"必修"、"rec"，列出本学系推荐；
  - 直接粘贴一整段文字（S3），逐行显示识别结果；
  - "sync"，执行同步（S1）。
- 键盘操作：方向键移动、空格勾选、Enter 加入所有已勾选的课；⌘Enter 加入全部结果。
- 下拉列表底部固定显示"已选 N · 学分 · 冲突"。
- 移动到某一行时，课表上用虚影块预览它的位置。

### 方案 E — 课程表格（像电子表格一样筛选和批量勾选）

**核心想法**：把本学期所有可选的课放进一张密集的表格，用筛选加批量勾选完成添加。

- 布局：左边约 65% 是可排序、可筛选的表格，右边约 35% 是缩小版课表（只看占用和冲突）。
- 表格列：勾选、代码、课名、时间、学分、推荐、学系、状态（已在课表 / 已修得 / 可加）。
- 表头上方有一排筛选小标签：本学系、推荐、必修、未修得、无冲突、某一天、某一节、语言；可以多选叠加。默认选中"本学系 + 未修得"。
- 勾选若干行后，表格底部出现操作条："已选 5 · 11 学分 · 1 冲突 [加入]"；勾选的同时，右侧小课表实时预览。
- 点小课表上的空格（S4），自动加上"某一天 + 某一节"的筛选；同步（S1）和粘贴（S3）在表格上方。粘贴后表格自动筛选出识别到的课，并把它们勾上。

## 6. 比较时关注什么（供使用者参考）

- 完成 S2（批量加推荐课）需要几次点击？
- 加之前能不能看清结果：总学分、冲突、占了哪些格子？
- S3 粘贴后，无法识别的代码和已修得的课够不够醒目？
- 在课表很满的周（15 门以上）时，界面还清楚吗？
- 第一次用，会不会找不到入口？
