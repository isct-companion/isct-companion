# 移动端原生壳 UX 设计初稿

状态：初稿，2026-10-13。基于 `refactor/rust-core` 分支的
[`core-consolidation.md`](../core-consolidation.md)、
[`product-definition.md`](../product-definition.md)、
[`school-refresh.md`](../school-refresh.md) 与
[`course-add-options.md`](course-add-options.md)。

## 1. 范围与前提

分支文档对前端 UX 只有三条硬约束，本稿全部围绕它们展开。

- **桌面不重设计。** 重新设计桌面 UI 是非目标。桌面 React 只是变薄：zustand
  退化为 core 读模型的缓存，页面不再自己判断"过期、冲突、到期"。
- **移动端壳层重做。** 旧的 Tauri 移动布局不是验收门槛；目标是 SwiftUI 与
  Jetpack Compose 原生壳。移动端 UX 可以从零设计，但只能消费 core 的读模型和
  事件。
- **Core 决定，壳层渲染。** 壳层只做三件事：渲染读模型、转发意图、实现平台端
  口。任何"这个数据意味着什么"的条件判断都不出现在 TS、Swift 或 Kotlin 里。

设计检验法：每个屏幕都必须能写成"订阅哪个读模型 + 发哪些意图"。写不出来的屏
幕，说明它在壳层里偷偷做了判断，设计上要砍掉。

### 移动端默认假设

- 组件要**大**：课表格子至少 64pt 高，主按钮 52pt，次按钮 44pt。
- 组件要**少**：每屏最多一个主操作，其余交给手势。
- 交互要**顺手**：下拉刷新代替刷新按钮，sheet 下滑代替关闭按钮，行内横滑代
  替每行的"…"菜单。
- 信息要**浅**：格子只显示课名和教室；细节留给 sheet。

## 2. 架构边界：壳层能看到什么

```text
壳层（桌面 React / iOS SwiftUI / Android Compose）
  │ 意图：拉取、加课、隐藏、打开            ▲ 读模型与事件：快照、进度、typed error
  ▼                                         │
isct-core：school · workspace · catalog · references · course_files · cloud · scheduler/tick · ocr
```

### 每个屏幕消费什么、发什么

这是 UX 与 FFI 之间的接口草案。壳层只允许用这张表里的东西。

| 屏幕 | 订阅的读模型 | 发出的意图 |
|---|---|---|
| 首页 | 今日视图（教学状态、分段课次、作业、学业摘要）、拉取快照、会话状态 | 手动拉取、隐藏作业、打开讲义、打开 Web |
| 课表 | 某周的时间平面（课、集中讲义、考试、计划）、本季推荐摘要 | 切换周、加入/移出计划、新建计划 |
| 讲义列表 | 本季度课程（按上课顺序）、每门课的作业计数 | 打开课程、请求课程详情填充 |
| 讲义详情 | 章节树、活动、文件缓存状态、展开状态 | 展开/折叠、打开文件、打开提交页、下载 |
| 加课 | 候选列表（已含推荐标记、冲突、已修得、学分合计） | 加入、移除、撤销 |
| Web | 当前服务、安全可恢复的 URL、返回来源 | 切换服务、导航 |
| 设置 | 账户卡片、凭据状态、参考数据状态、云同步状态 | 登录、忘记凭据、刷新来源、连接云 |

候选列表到达壳层时已经带着冲突和"已修得"标记；壳层不计算。

## 3. 导航

底部五个 tab：**首页 · 课表 · 讲义 · Web · 设置**。五个是 iOS 与 Android 的
系统推荐上限，不再加。

- 首页只放"今天"，不放周课表和卡片拼盘。
- 课表是一等目的地，周视图从首页移走。
- 再点当前 tab 回到该 tab 的根；在 Web 内再点 Web 弹服务 sheet。
- 连接状态是首页右上角一个点，点开是 sheet；只有出问题才升级成横幅。
- 课表 tab 和讲义 tab 都能进讲义详情，返回时回到各自 tab 的根。从讲义进入
  Web 时返回回讲义，与桌面的 `← Course` 是同一机制。

## 4. 屏幕

### 4.1 首页（今天）

顺序固定，每一项是 core 的一个读模型，壳层不排序不过滤：

1. 日期与教学状态（平常授课日 / 休日 / 休讲日 / 振替日），右上角连接状态点。
2. 现在在上的课：大卡片，时间与教室视觉最重。之后的课：一行一节。
3. 作业：已过期、今天、临近；只用 LMS 官方状态，没有本地"标记完成"。
4. 学业摘要：GPA、GPT、已修学分。

手势：日期行横滑换天，长按回到今天；下拉手动拉取，进度环在顶部。

### 4.2 课表

- 顶部：季度名、上一周 / 本周 / 下一周，40pt 触控区。
- 主体：周一到周五 × 1–10 节，格子 64pt 高，两行：课名、教室。最下一行
  "集中 · 其他"。状态按产品定义的四种强度显示（登録实色、申告实色加标记、
  LMS 虚线、计划低对比）。今天那一列的日期高亮，正在上的格子加描边。
- 顶部可收起横条："本季推荐 · 一键加入 N 门"，只在当前季度有未加入的推荐课
  时出现。
- 点占用格子：底部 sheet，显示时段、代码、课名、教室、学分、状态，四个大按钮：
  讲义、教室、LMS 页面、移出计划。
- 点空格子：sheet 列出该时段候选，推荐在前，点一下即加入；长按候选在课表上
  预览占格，松手即加入。
- 每次加入后底部出现"已加入 N 门 · 撤销"条，6 秒。撤销结果来自 core。
- 不做拖动格子换时间：学校课表不可改。

桌面的批量加课采用 `course-add-options.md` 的方案 A（建议清单），因为"app
已经知道你要上什么"正是 core 算出来的；移动端不出现勾选清单，改为上面的横条
与空格子候选。

### 4.3 讲义

- 列表：本季课程按上课顺序，每行课名、时间、作业计数。
- 详情：桌面 Lecture Desk 的单列版。顶部四页横滑：内容 / 作业 / 资料 / 大纲。
  章节用展开面板，展开状态由 core 记住。
- 文档打开后全屏，下滑退回章节并释放文档。移动端每门课只保留一个全屏文档
  （桌面是五个 tab，只挂载当前一个）。
- 底部两个按钮：在 Web 打开、提交页。两者都切到 Web tab 并导航到精确 URL，
  带 `← 讲义` 返回，不弹第二个 WebView。

### 4.4 Web（方案 B：沉浸式，底部迷你栏）

- WebView 占满，底部一条胶囊迷你栏：返回、服务名（点开服务 sheet）、在浏览
  器打开。页面上滑时迷你栏自动收起。
- 再点 Web tab 或点服务名：服务 sheet，列出 LMS、教務Web、Mail、Syllabus、
  Portal、図書館。
- 有来源时，`← 讲义` 显示在迷你栏左侧，替代普通返回；浏览器前进后退留在服
  务内。
- 桌面向页面显示一条"建议用电脑 · 在浏览器打开"状态，不弹对话框。
- 横屏提示只在页面主任务在当前宽度下不可用时出现一次。
- iPad 横屏改用顶部服务条形态（方案 A），宽屏不心疼空间。

未采用：方案 C（服务首页网格）信息价值高但多一层；如果后续需要"最近打开"与
服务状态摘要，可以作为服务 sheet 的内容加回来。

### 4.5 设置

- 根页：可搜索列表（中・日・英），每行一句现状摘要，不进子页也能看到状态。
  日常项：学校账户、学习档案、通知、校历、外观与语言、备份与同步、已隐藏的作
  业。高级三项（数据更新、自动化、开发者选项）折成一行。
- 子页：每屏一个主卡片。主操作 52pt，次操作 44pt，危险操作只用红色文字区分，
  放在卡片最后一行。
- 学校账户：Science Tokyo 与 Tokyo Tech 两张卡，各有状态点、用户名、凭据状
  态、刷新记录、上次页面、重新登录、忘记凭据。
- 首次启动不做引导页：直接进真实的空首页，账户子页加一个"跳过"。
- 校园 Wi-Fi 行在没有端口实现的平台上整个不存在，不是置灰。

## 5. 手势词汇表

一个手势在全 app 里只有一种含义。

| 手势 | 含义 | 用在哪 |
|---|---|---|
| 点一下 | 打开 | 课表格子 → sheet；空格子 → 候选；课次/作业 → 讲义详情 |
| 长按 | 快捷动作 | 格子：移出、换色、复制代码；作业行：隐藏/提交页；候选：预览占格；文件：下载/分享 |
| 横滑 | 换时间 / 换对象 | 课表换周；首页换天；讲义详情换页；左缘留给系统返回 |
| 竖向 | 刷新 / 关闭 | 列表下拉拉取；sheet 下滑关闭；文档下滑退回 |
| 行内横滑 | 单行动作 | 作业行右滑隐藏、左滑提交页；候选行右滑加入；计划行左滑删除 |

不做：拖格子换时间、双击与多指手势、同一手势两种含义、长按菜单超过 4 项。
Android 上行内横滑从左缘 20pt 以内不起始，避开系统返回手势；此点需在
Compose 壳里验证。

手势只是意图的入口。长按作业行"隐藏"和点按钮"隐藏"发给 core 的是同一个意
图；撤销条也来自 core 返回的变更结果。

## 6. 状态反馈

拉取状态机有 11 个有限状态（`PullState`），事件与快照分开。UI 不维护 busy
标志，只把快照映射成三档显示。

| 档 | 状态 | 显示 |
|---|---|---|
| 安静 | Succeeded · Queued · Checking | 首页右上角绿点，无文字；sheet 里"上次检查 12:40" |
| 进行中 | Running · Applying · Yielding | 点变进度环，来自 `SchoolPullProgress` 的 completed/total；手动拉取时 sheet 显示"LMS · 第 4/12 门"；Applying 后取消按钮消失 |
| 需要你 | Failed · Blocked · RetryWaiting | 首页顶部横幅，文案来自 typed error，带一个动作 |

横幅动作与 `CoreError` 的对应：`NeedsSignIn` → 登录；`Network` → 重试或
"离线，显示的是 12:40 的数据"；`SiteChanged` → 在 Web 打开，并说明已保留成功
读取的页数；`Busy`（OCR）→ "正在识别上一张"。

壳层不改写文案。若 i18n 留在壳层，core 需要暴露稳定的错误码而不是字符串。

## 7. 平台差异：编译期隔离

- **周期唤醒**：桌面定时器驱动 `Core::tick`；iOS 用 BGAppRefreshTask，
  Android 用 WorkManager。UI 无轮询，前台/网络/蜂窝事实由壳层上报，是否拉取
  由 core 决定。
- **Matrix 表 OCR**：移动端必备。HEIC → JPEG 在壳层完成，原始字节交给 OCR
  crate；进度来自 `OcrProgress`。
- **校园 Wi-Fi**：core 持策略，各端实现 `CampusWifi` 端口。
- **学校 WebView**：壳层创建、布局、隐藏；core 只驱动导航和脚本。离开 Web
  先排队隐藏再切路由，回来时同一会话。
- **iOS 与 iPadOS**：一个二进制，允许运行时区分。iPad 横屏用两栏布局。

## 8. 三个壳层怎么像同一个 app

不共用组件代码；共用三样东西，交给系统一组东西。

### 共用（生成，不手抄）

- **Token**：`design/tokens.json` 一处定义颜色、字号、字重、间距、圆角；脚本
  生成桌面 CSS 变量（Mantine 主题读同一组值）、Swift 的 Color/Font 扩展、
  Compose 的 ColorScheme/Typography。
- **文案**：现有 `src/i18n/*.json`，同一脚本生成 iOS 字符串目录与 Android
  `strings.xml`。
- **课程色**：现在在 TS 里按布局算。要三端同一门课同一色，分配规则进 core
  作为读模型的字段（依赖课程 ID 的稳定排序），不留在壳层。

### 交给系统（故意不统一）

底部 tab、导航栏、返回手势、sheet、列表、开关、搜索框、系统字体、动效、触
感反馈。强行自绘这些会让 app 在每个平台上都"不对劲"。

### 自绘（三端同一规格，各写一遍）

课表格子、课次行、作业行、状态点、进度环、横幅、撤销条、推荐/冲突标记、课程
色块。规格写在本目录下，每个组件给尺寸、状态、手势和读模型字段；桌面用
React、iOS 用 SwiftUI、Android 用 Compose 各实现一次。

字体只定义字号和字重，不定义字体族：桌面 web 字体、iOS SF、Android
Roboto，才能拿到各平台的日文渲染与动态字号。
