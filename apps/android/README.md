# Android app

Jetpack Compose shell over the Rust core (`crates/isct-core` through the Kotlin
SDK in `bindings/kotlin`). It is a screen-for-screen translation of the SwiftUI
shell, so both phones look and behave alike: the shell renders Core read models,
forwards intents and implements the platform ports; it keeps no business state
of its own. Design: [docs/ux/mobile.md](../../docs/ux/mobile.md).

## Build and run

Needs JDK 17+, the Android SDK (platform 35, build tools), NDK 28 and the Rust
Android targets (`rustup target add aarch64-linux-android x86_64-linux-android`).
Build the Core SDK first; the app links `bindings/kotlin/artifacts/isct-core.aar`.

```bash
ISCT_SDK_PROFILE=dev ANDROID_HOME=~/Library/Android/sdk NDK_HOME=~/Library/Android/sdk/ndk/28.2.13676358 node scripts/bindings/build-android.mjs --no-ocr
```

```bash
cd apps/android && ./gradlew :app:installDebug
```

Drop `--no-ocr` for the arm64 OCR runtime that reads the Matrix card. The
x86_64 emulator slice always reports OCR unavailable, so the Matrix page there
offers only paste and manual entry. Rebuild the AAR whenever
Core changes: UniFFI checks signatures when the library loads.

## Layout

| Path | Content |
|---|---|
| `core/AppModel.kt` | Owns the `Session`: subscription, read models (`today`, `assignmentBoard`, `scheduleView`, `courseDetail`), intents, lifecycle facts |
| `core/SchoolBrowserHost.kt` | `NativeBrowser`: one resident WebView per school site, driven by Core; injects Core's scripts after each load |
| `core/WebRouter.kt` | Which school page is on screen; `openSchool` and the visibility fact |
| `core/KeystoreVault.kt` | `NativeVault`: secrets sealed with an Android Keystore AES-GCM key, kept on this device |
| `core/NotificationScheduler.kt` | Schedules Core's `notificationPlan` as alarms (64 pending at most) |
| `features/*` | 今日 · 時間割 · 課題 · ウェブ, course detail, settings sheet |
| `app/isct/design/IsctTokens*.kt` | Tokens generated by `yarn design:tokens`; do not edit |

## Differences from iOS

- 課題 renders the quarter's one Core task timeline (`AssignmentBoard.today`),
  the same groups desktop shows; the bottom row opens the full record
  (`AssignmentBoard.record`) with submitted work and hidden rows to restore.
- Logins stay on the device (Keystore); there is no iCloud Keychain to share
  them with the desktop app.
- Reminders are exact alarms once the person allows exact alarms in system
  settings; otherwise Android may deliver them up to 10 minutes late.

## Verified

On an API 35 x86_64 emulator against a copy of a real desktop `school.db`:
first launch shows the connect card; 今日 (no-class day), 時間割 with week
swipe, 課題 with swipe hide, undo, pin and restore from the record, course
detail, the pushed T2SCHOLA page and the ウェブ tab (SSO login page in the
resident WebView), the settings sheet, the notification permission prompt and
the alarms scheduled from Core's plan, light and dark. Not exercised: sign-in
past the login page, pulls, and a reminder actually firing.

The dev-profile SDK takes about 30 s to open the session on that emulator;
build the SDK with the release profile for real use.
