# Android app

Jetpack Compose shell over the Rust core (`crates/app-core` through the Kotlin
SDK in `bindings/kotlin`). It is a screen-for-screen translation of the SwiftUI
shell, so both phones look and behave alike: the shell renders Core read models,
forwards intents and implements the platform ports; it keeps no business state
of its own. Design: the `approach/mobile-*` decisions in [STATUS.md](../../STATUS.md).

## Build and run

Needs a JDK 17 or newer (`JAVA_HOME`), `kotlinc` on `PATH`, the Android SDK
(platforms 34 and 37, build tools), NDK 28 and the Rust Android targets
(`rustup target add aarch64-linux-android x86_64-linux-android`). The app links
the Core SDK at `bindings/kotlin/artifacts/app-core.aar`; one command builds
it and then the debug APK:

```bash
yarn android:debug
```

Without `ANDROID_HOME`/`NDK_HOME` the builder takes the SDK from
`apps/android/local.properties` (Android Studio writes it) and the NDK version
`app/build.gradle.kts` pins. `sdk:android` builds only the AAR;
`ISCT_SDK_PROFILE=dev` builds Core faster but opens the session slowly.

On Windows: Android Studio's bundled JDK works. Its Kotlin plugin compiler is
not a full distribution; put the standalone `kotlin-compiler-2.2.21` (the
version CI pins) on `PATH`, unzipped to a folder whose name is at most eight
characters with no dot (e.g. `%USERPROFILE%\tools\kt2221`), since `kotlinc.bat`
otherwise starts from the 8.3 short path and misses its own stdlib
("unresolved reference 'println'"). yarn 4 needs `corepack enable` once.

```bash
cd apps/android && ./gradlew :app:installDebug
```

`--no-ocr` leaves out the arm64 OCR runtime that reads the Matrix card. The app
packages arm64 only (`abiFilters`); run it on a phone or an arm64 emulator
image. Rebuild the AAR whenever Core changes:
UniFFI checks signatures when the library loads.

| `BackgroundWake.kt` | The WorkManager wake that runs Core's `backgroundWake` out of front |

## Differences from iOS

- 今日's 課題 renders the quarter's one Core task timeline (`AssignmentBoard.today`),
  the same groups desktop shows; すべて opens the full record
  (`AssignmentBoard.record`) with submitted work and hidden rows to restore.
- The campus map draws with MapLibre over OpenFreeMap's base map rather than
  MapKit over Apple's; footprints sit under the base map's labels and the
  floor above them, as on iOS. Its marks are drawn by the map itself, so a
  screen reader does not read them. The panel stays at the bottom on every
  window size (iOS moves it to the leading edge in a wide one) and its card
  folds in one step rather than following the finger; the position button
  follows the person until they move the map, with no heading mode.
- Logins stay on the device (Keystore); there is no iCloud Keychain to share
  them with the desktop app.
- The quarter export is a share button in the 時間割 header rather than a long
  press on the tab, and opened files go to a viewer app instead of Quick Look.
- 授業 is a tab only on windows at least 600 dp wide; there is no two-pane
  split beside the course list yet.
- Reminders are exact alarms once the person allows exact alarms in system
  settings; otherwise Android may deliver them up to 10 minutes late.
- First-run tips (`design/Guide.kt`, modelled on desktop's `guide.tsx`) cover
  the week swipe with session marks, lesson marks, assignment swipes and the
  ウェブ title's site list.
- Hiding an assignment by swiping left commits once the row passes the
  threshold, with the system snackbar's undo; iOS reveals a 非表示 button and
  never hides on a long pull alone. The Material swipe-to-dismiss row has no
  revealed-button state, and the undo covers the slip.
- ウェブ switches sites from its title as iOS does, but has no long press on
  the tab item: Material's navigation bar offers none. Our floating controls
  are Material surfaces, not Liquid Glass; the motion (`design/Motion.kt`:
  rolling figures, a course growing out of what was tapped) is Compose's own.

## Verified

On an API 35 x86_64 emulator against a copy of a real desktop `school.db`:
first launch shows the connect card; 今日 (no-class day), 時間割 with week
swipe, 課題 with swipe hide, undo, pin and restore from the record, course
detail, the pushed T2SCHOLA page and the ウェブ tab (SSO login page in the
resident WebView), the settings sheet, the notification permission prompt and
the alarms scheduled from Core's plan, light and dark. Not exercised: sign-in
past the login page, pulls, and a reminder actually firing.

The dev-profile SDK takes about 30 s to open the session on that emulator;
build the SDK with the release profile for real use.

## Not yet

Recognition of a real Matrix card on an arm64 device, Google Drive sign-in on a
device (needs the Android OAuth client registered with the signing
certificate's SHA-1), widgets (Glance) and the tablet two-pane 授業 split.

UI strings are keyed by namespaced message keys (`settings.reset.caches.title`)
and read at runtime from the desktop's `resources/locales` catalogs, packaged
as assets (`design/Localization.kt`), so the language follows
`settings.locale`. `en.json` holds every key with its English copy; a test in
`apps/desktop/tests` checks that each key used here exists.
